## Summary

The codebase is well-structured for its scope, with clear separation between data, store, and UI layers. The `skipHydration` + `StoreHydration` provider pattern is the correct approach for Zustand v5 with SSR. Most issues below fall into the "Needs Work" tier. There are no critical security holes, but several patterns will cause real pain when the project grows.

---

## 1. Architecture & Design — Good (with caveats)

The layering is sensible: static data → Zustand store → thin page shells → feature components.

**Issues:**

- **Nested `<main>` on the Analytics page.** `src/app/analytics/page.tsx:5` renders its own `<main>`, but `src/app/layout.tsx:22` already wraps all children in a `<main>`. This produces nested `<main>` elements — invalid HTML, doubled padding, and an accessibility violation (only one `<main>` per page).

- **Stale export in module page.** `src/app/module/[id]/page.tsx:3` exports `export const instant = false`. This is not a valid Next.js segment option and does nothing — remove it.

- **`useHydrated` hook is defined but never used.** `src/hooks/useHydrated.ts` exports a hook that reads `_hasHydrated`, but no component ever imports it. The `_hasHydrated` flag exists in the store with no consumer — if the intent was to block renders until hydration completes, that guard was never wired up.

- **`TopicTypeIcon` component is dead code.** `src/components/ui/TopicTypeIcon.tsx` is defined but not imported anywhere. The project uses `TopicIcon` instead.

## 2. Code Quality — Needs Work

**Major: The topic notes UI is copy-pasted verbatim between two components.**

`src/components/module/ModuleDetail.tsx` lines 22–133 and `src/components/timeline/TimelineView.tsx` lines 16–151 contain identical implementations of:
- `toggleNotes` / `startEditing` / `stopEditing` functions
- The notes `<textarea>` / read-view toggle block
- The `expandedNotes` and `editingNotes` state

This is ~80 lines of duplicated logic. A `useTopicNotes(topicId)` hook plus a `<TopicNotesPanel>` component would eliminate the duplication entirely.

**Minor issues:**

- `src/app/page.tsx:10–11`: `modules.flatMap(...)` is called twice to compute `totalTopics` and `doneTopics`. A single `flatMap` call should be shared.

- `src/components/overview/ModuleCard.tsx:8`: `TYPE_COUNTS` is named in `SCREAMING_SNAKE_CASE` but is a function, not a constant. Should be `getTypeCounts` or `countByType`.

- `src/components/overview/ModuleCard.tsx:15`: The component re-selects the same module's topics from the store despite the caller already having the full `Module` object. The extra selector adds overhead without benefit.

- `src/components/analytics/AnalyticsView.tsx:86`: Overall percentage is computed inline, duplicating what `getGlobalProgress()` in the store already does.

## 3. Type Safety — Good

No raw `any` usages in application code. The OpenAI error handler in `src/app/api/chat/route.ts:18` correctly uses `err: unknown` with type-narrowing.

**One concern:**

- `src/components/assistant/AIAssistant.tsx:12`: `buildSystemPrompt`'s parameter is typed as `ReturnType<typeof useProgressStore.getState>['modules']`. This is fragile — it ties the helper to the store's internal shape. A cleaner type is `Module[]` imported from `@/types`.

## 4. Performance — Needs Work

**Progress percentage recomputed in four separate places on every render:**

1. `src/components/layout/Navbar.tsx:40` — iterates all topics inline
2. `src/app/page.tsx:9` — calls `getGlobalProgress()` from the store
3. `src/app/page.tsx:10–11` — also calls `flatMap` twice for counts
4. `src/components/analytics/AnalyticsView.tsx:86` — recomputes inline again

All inline recomputations should use the store's selectors consistently.

**`getTopicIcon` runs a 50-rule regex scan on every render:**

`src/lib/topicIcons.ts:159–164`: iterates up to 50 regex patterns on each topic title per render. With ~60 topics visible on a timeline page, that is up to 3,000 regex tests per render. Topic titles never change — memoize with a `Map<string, LucideIcon>` cache.

**Weekly velocity in `AnalyticsView` does O(n × 8) work per render:**

`src/components/analytics/AnalyticsView.tsx:56–67`: For each of 8 weeks, it calls `allTopics.filter(...)` over every topic. A single-pass group-by-week would be cleaner.

**`AIAssistant` rebuilds the full system prompt on every render:**

`src/components/assistant/AIAssistant.tsx:46`: `buildSystemPrompt` is called unconditionally inside the render. Wrap in `useMemo(() => buildSystemPrompt(modules), [modules])`.

## 6. AI Integration — Needs Work

`src/app/api/chat/route.ts`:

- **No input validation or size limit (line 10).** `const { messages } = await req.json()` accepts whatever the client sends. A malicious client can send thousands of messages or multi-megabyte strings, forwarding them directly to the LLM API. At minimum, validate `messages` is an array and enforce a max-message-count and per-message character limit.

- **No rate limiting.** The endpoint is unauthenticated. Anyone who finds the URL can spam the AI API.

- **Empty API key silently accepted.** `process.env.AI_API_KEY ?? ''` — if the env var is missing, the client is constructed with an empty string and fails opaquely at network time. Fail fast at startup instead.

- **`AI_BASE_URL` may be `undefined`.** Passed directly with no fallback — silently routes to `api.openai.com` instead of the intended custom endpoint if the env var is missing.

- **Full conversation history sent on every turn.** No truncation — a long conversation will eventually exceed the model's context window and start returning errors.

## 7. UX / Accessibility — Needs Work

- **AI chat toggle button** (`AIAssistant.tsx:61–67`) uses Unicode glyphs (`×`, `✦`) with no `aria-label`. Screen readers will misannounce them. Add `aria-label={open ? 'Close AI Coach' : 'Open AI Coach'}`.

- **`StatusChip` has no undo.** Cycling from `done` back to `not_started` is one accidental click away with no recovery path.

- **Notes Edit button hidden from keyboard users** (`ModuleDetail.tsx:126`). The `opacity-0 group-hover:opacity-100` pattern hides it from keyboard-only users who never trigger hover.

- **`TopicIcon` icons have no accessible text** (`src/components/ui/TopicIcon.tsx:11`). Rendered with no `aria-label` and no adjacent description.

- **Chat message list uses array index as React key** (`AIAssistant.tsx:83`). Fragile if the list is ever reordered or spliced.

- **Analytics bar charts have no accessible text.** Weekly velocity and day-of-week charts are pure visual `<div>` bars with no ARIA roles, no accessible axis labels, and no screen-reader summary.
